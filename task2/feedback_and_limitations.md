# Feedback, Validation and Project Limitations

## 1. Purpose

This document describes the approach for gathering feedback and validating the proposed curriculum redesign. It also identifies limitations that may affect the findings and recommendations.

The purpose is to ensure that the proposed changes are evidence-based, practical and transparent.

## 2. Feedback Approach

Feedback from faculty members and graduates can help assess whether the proposed curriculum improvements are relevant to academic learning and workplace expectations.

The following questions can be used for voluntary feedback:

1. Which technical skills should students strengthen before graduation?
2. Are the practical exercises in existing courses sufficient for applying theoretical concepts?
3. Which topics would benefit from more hands-on learning?
4. Are any topics repeated across different courses?
5. What improvements would make students better prepared for internships and entry-level roles?

Feedback should be recorded accurately, with the date, respondent category and permission to use the response where appropriate. Personal information should not be published without consent.

## 3. Feedback Status

Feedback status should reflect what has actually been completed.

If feedback is obtained, record the date, respondent category, questions asked, key points raised and resulting changes to the proposal.

If faculty or graduate feedback cannot be obtained before submission, document that limitation honestly. The curriculum analysis can still proceed using the official programme structure, available course material and job descriptions.

No feedback responses should be invented or presented as real.

## 4. Validation Approach

The proposed redesign can be checked using the following methods:

| Area | Validation method | Expected evidence |
|---|---|---|
| Course structure | Compare the proposed map with the applicable official curriculum | Semester-wise course and credit map |
| Industry relevance | Compare course topics with real job descriptions | Skills-to-course comparison |
| Course overlap | Compare detailed syllabi and learning outcomes | Documented overlap analysis |
| AI-assisted exercises | Run the prompts, inspect outputs and perform the stated checks | Actual test results and verification notes |
| Credit allocation | Recalculate affected and total programme credits | Transparent credit calculation |
| Proposed workflow project | Test the workflow against defined synthetic cases | Test-case outcomes and limitations |

These are validation methods. Results should be reported only after the corresponding checks have been performed.

## 5. Project Limitations

### 5.1 Limited job-description sample

The job-market analysis uses a small number of postings. It identifies examples of employer requirements but cannot represent every AI, machine-learning or data-related role.

### 5.2 Course-content detail

Course titles alone cannot establish how much time is allocated to each topic or how deeply it is taught. Detailed syllabi, handouts, laboratory exercises and assessments are needed to determine whether a topic is missing or duplicated.

### 5.3 Rapidly changing technology

Generative AI frameworks, deployment tools and industry practices change quickly. The proposed improvements should emphasise transferable concepts, evaluation and responsible use alongside specific tools.

### 5.4 Credit and regulatory constraints

Changes to course credits may be restricted by programme requirements, prerequisites or academic regulations. The proposal therefore requires review before any formal implementation.

### 5.5 Feedback availability

The depth of stakeholder feedback depends on whether faculty members or graduates are available and willing to participate. Where feedback is unavailable, this should be stated rather than replaced with assumed opinions.

### 5.6 AI-generated content

AI-generated explanations and code may contain mistakes, omissions or unsupported claims. Outputs require independent checking, and test results must reflect actual execution.

## 6. Ethical and Responsible Practices

The project follows these principles:

- Use public job descriptions and official curriculum material where available.
- Distinguish observed information from assumptions and recommendations.
- Do not fabricate interviews, feedback, measurements or test results.
- Protect personal and confidential information.
- Document AI assistance and verify technical outputs.
- Present curriculum changes as proposals rather than approved university decisions.

## 7. Conclusion

The curriculum redesign is intended to support informed academic discussion, not to replace formal curriculum review. Its quality depends on the accuracy of the course map, the relevance of the evidence, transparent calculations and honest reporting of limitations.

Further validation through detailed syllabus review and voluntary stakeholder feedback can strengthen the recommendations before implementation.
